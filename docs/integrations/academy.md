# Связка академии с платформой NMNH.TRADE

Ученик один и тот же: в академии он проходит уроки, в кабинете видит сигналы,
монеты у него общие. Ключи связки — `tg_id` и `weex_uid`, оба хранятся в
`Student`, бот использует тот же UID.

## 1. Начисление монет из академии

```
POST https://api.nmnh.trade/api/coins/grant
X-Service-Key: <SERVICE_API_KEY>
Content-Type: application/json
```

Тело:

| поле | тип | обязательно | смысл |
|---|---|---|---|
| `tg_id` | int | один из двух | Telegram ID ученика |
| `weex_uid` | string | один из двух | UID на WEEX |
| `ref` | string | да | идентификатор события: `module_3`, `test_7`, `invite_881` |
| `reason` | string | нет | тип события, задаёт тариф; по умолчанию `academy` |
| `amount` | int | нет | явная сумма; если не задана, берётся тариф по `reason` |
| `username` | string | нет | ник, если ученика придётся заводить |

Ответ:

```json
{
  "student_id": 42,
  "balance": 165,
  "added": 15,
  "granted": true,
  "student_created": false
}
```

`granted: false` и `added: 0` означают, что событие с таким `ref` у этого
ученика уже начислено. **Это не ошибка**: академия может слать событие сколько
угодно раз, повтор просто ничего не изменит. Защита стоит на уникальном индексе
`(student_id, ref)`, поэтому её не обойдут и два одновременных запроса.

`student_created: true` — ученика завели прямо сейчас. Так бывает у тех, кто
учится, но в кабинет ни разу не заходил: начислять всё равно надо, иначе монеты
потеряются. Такая запись создаётся с `is_approved = false` — доступ к сигналам
выдаёт ментор, академия его не раздаёт.

### Тарифы

| `reason` | монет |
|---|---|
| `academy_joined` | 10 |
| `lesson_watched` | 5 |
| `homework_accepted` | 10 |
| `module_completed` | 15 |
| `test_passed` | 25 |
| `friend_invited` | 25 |
| `verification` | 50 |
| `friend_verified` | 75 |
| `course_completed` | 100 |

Незнакомый `reason` оплачивается по ставке `common` — 10 монет. Тарифы лежат в
`ACADEMY_REWARDS` (`backend/api/coins.py`), правятся там же.

### Пример

```bash
curl -X POST https://api.nmnh.trade/api/coins/grant \
  -H "X-Service-Key: $SERVICE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"tg_id": 123456789, "ref": "module_3", "reason": "module_completed"}'
```

### Коды ответа

| код | причина |
|---|---|
| 200 | начислено или признано повтором (смотри `granted`) |
| 400 | нет ни `tg_id`, ни `weex_uid`; либо `amount` ≤ 0 |
| 401 | неверный `X-Service-Key` |
| 503 | `SERVICE_API_KEY` не задан на бэкенде — интеграция не настроена |

## 2. Секретный ключ

Генерация:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Кладётся в `.env` бэкенда:

```
SERVICE_API_KEY=<сгенерированное значение>
```

и в конфиг сервера академии. После правки `.env` бэкенд надо перезапустить.

Пока переменная пустая, ручка отвечает `503` и ничего не начисляет — открывать
её без ключа нельзя, иначе монеты сможет выписать себе кто угодно.

Ключ не коммитится: `.env` в `.gitignore`.

## 3. Адрес бэкенда

```
https://api.nmnh.trade
```

Постоянный, за Cloudflare Tunnel. Проверка живости — `GET /api/health`,
отвечает `{"status":"ok",...}` без авторизации.

Подробности туннеля: `docs/deploy/cloudflare-tunnel.md`.

## 4. База данных

Адрес задаётся `DATABASE_URL`. Сейчас на удалённом рабочем столе это SQLite:

```
sqlite:///nmnh_dev.sqlite3
```

Путь относительный, файл лежит рядом с проектом:

```
C:\Users\Администратор\Desktop\WEEX\MENTOR\nmnh_dev.sqlite3
```

**Перезапуск переживает** — это обычный файл на диске, а не память. Данные
теряются только вместе с файлом.

**Резервных копий нет.** Это главный риск: один удалённый рабочий стол, один
файл, никаких копий. Пока их не настроили, минимальный вариант — ежедневная
задача в планировщике Windows:

```powershell
$src = "C:\Users\Администратор\Desktop\WEEX\MENTOR\nmnh_dev.sqlite3"
$dst = "C:\Backups\nmnh_$(Get-Date -Format yyyy-MM-dd).sqlite3"
New-Item -ItemType Directory -Force -Path "C:\Backups" | Out-Null
Copy-Item $src $dst
# Держим копии за 30 дней
Get-ChildItem C:\Backups\nmnh_*.sqlite3 |
  Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-30) } | Remove-Item
```

Копировать файл на ходу безопасно: SQLite допускает чтение при работающих
записях, а бэкенд пишет короткими транзакциями.

Дальнейший шаг — переезд на PostgreSQL: в коде для этого ничего менять не
нужно, только `DATABASE_URL`. Тогда появятся нормальные бэкапы и одновременный
доступ нескольких процессов.

## 5. Миграция

Перед первым использованием ручки на существующей базе:

```bash
python migrate_academy_link.py
```

Скрипт добавляет в `students` колонки `created_via`, `first_login_at`,
`last_login_at`, `login_count`, убирает дубли начислений и вешает уникальный
индекс `(student_id, ref)`. Идемпотентен, повторный запуск безопасен.

## 6. Экраны для ученика

Монеты и магазин уже есть в кабинете — из академии веди сюда:

| что | адрес |
|---|---|
| Магазин (баланс монет в шапке) | `https://www.nmnh.trade/app/shop` |
| Профиль | `https://www.nmnh.trade/app/profile` |
| Дашборд | `https://www.nmnh.trade/app/dashboard` |

Вход в кабинет — по WEEX UID на `https://www.nmnh.trade`. Ученик, заведённый
из академии, войдёт по тому же UID и увидит накопленные монеты.

Проверить, что тратить есть на что:

```bash
python check_shop.py
```

## 7. Кто заходил на платформу

В админке `/admin/students` у каждого ученика видно: когда заходил последний
раз, сколько раз всего и откуда взялась запись (бот, сайт, академия). Сверху —
сводка: сколько человек заходили хоть раз, сколько не заходили ни разу, сколько
активны за неделю.

Ученик, заведённый академией и ни разу не открывший кабинет, показывается как
«не заходил» — это и есть та часть аудитории, до которой платформа пока не
дотянулась.
